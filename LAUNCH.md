## The project, in one paragraph

Use this as the source for every description below. It is accurate as written.

> FormatPort is a collection of 25 browser-based developer utilities for
> working with common data formats: converting between JSON, YAML, TOML, CSV,
> TSV, XML and HTML tables; generating TypeScript, Zod, Python, Go, SQL and
> JSON Schema from a JSON sample; decoding JWTs; Base64 and URL encoding;
> translating cURL commands into fetch, axios or Python requests; hashing;
> Unix timestamp conversion; UUID and ULID generation; case conversion; regex
> testing; and text diffing. Everything runs in the browser — nothing is
> uploaded, there is no account, and there is no backend.

**The differentiator, stated precisely.** Plenty of tools claim local
processing. This one ships a Content-Security-Policy with `connect-src 'none'`,
which means the browser itself refuses any outbound connection the page might
attempt, and anyone can verify it in one command:

```bash
curl -sI https://formatport.com/ | grep -i content-security-policy
```

That is the claim worth leading with, because it is the one a skeptical reader
can check in ten seconds without trusting you.

## GitHub README intro

Short and technical. The current README opens close to this already; this is
the version that names the product and the URL first.

```markdown
# FormatPort

**[formatport.com](https://formatport.com)** — 25 developer utilities that run
entirely in your browser.

Convert between JSON, YAML, TOML, CSV, TSV, XML and HTML tables in any
direction. Generate TypeScript, Zod, Python, Go, SQL or JSON Schema from a JSON
sample. Decode JWTs, encode Base64 and URLs, translate cURL commands, hash text
or files, convert Unix timestamps, generate UUIDs and ULIDs, convert case, test
regexes, diff text.

No backend, no build step, no framework: plain ES modules served as static
files. Every conversion is parsed and generated by JavaScript in your own tab,
so nothing you paste, drop or open is uploaded anywhere — and that is enforced,
not just promised, by a `connect-src 'none'` Content-Security-Policy the
browser applies whether the code behaves or not.

Test suite runs in the browser at [/tests/](https://formatport.com/tests/).
MIT licensed.
```

Consider renaming the repository from `convertor` to `formatport`. GitHub

## Show HN

HN's audience is the best match for this project and the least tolerant of
marketing language. Post it plain.

**Title** (80 char limit — this is 71):

```
Show HN: FormatPort – 25 developer converters that run entirely in your browser
```

**URL field:** `https://formatport.com`
**Text field:** leave empty. Put the following as the first comment, from your
own account, immediately after posting.

```
I kept pasting production JWTs and customer CSVs into whatever converter came
up first in search, and then feeling bad about it. Every one of those sites
says it processes locally. There is no way to tell from the outside whether
that is true.

So the constraint I set for this one was that the claim should be checkable by
someone who does not trust me. The site ships a Content-Security-Policy with
connect-src 'none', which means the browser refuses any outbound connection the
page tries to make — fetch, XHR, WebSocket, beacon, all of it — regardless of
what the JavaScript does. You can verify it without reading any of my code:

    curl -sI https://formatport.com/ | grep -i content-security-policy

There is no backend and no build step either. It is plain ES modules served as
static files, which is partly taste and partly because a build step is one more
place for something to get inserted between the source and what you run.

The parts that were harder than expected: CSV delimiter and header-row
detection are both guesses that are sometimes wrong, so the status line says
which way it went rather than silently picking; and the regex tester runs in a
Web Worker with a timeout, because a catastrophic backtrack in the main thread
takes the page with it.

25 tools — format conversion across JSON/YAML/TOML/CSV/TSV/XML/HTML, codegen to
TypeScript/Zod/Python/Go/SQL/JSON-Schema, JWT decode, Base64, cURL translation,
hashes, timestamps, UUID/ULID, case, regex, diff.

Test suite runs in the browser at /tests/ if you want to see what is actually
covered. MIT.

What I would most like to know: which tool you reached for first, and which one
you expected to be there and wasn't.
```

**How to post well**

- Post Tuesday–Thursday, roughly 08:00–11:00 US Eastern. Avoid weekends.
- Stay at the keyboard for the next three hours. The comments *are* the launch;
  a post whose author vanishes gets far less traffic regardless of votes.
- Answer criticism directly, including about the tools that already exist. "Yes,
  transform.tools does that too" is a fine answer.
- Never ask anyone to upvote. It is the one thing that reliably kills a post.
- Post once. If it sinks, it sinks — reposting is against the guidelines.

## Accuracy rules for anything written here

The whole pitch is "this claim is checkable". One wrong claim costs that, and
it is not recoverable in the comments.

**True, and safe to say:**

- 25 tools; everything runs in the browser; nothing is uploaded.
- `connect-src 'none'` is served in production and is verifiable with curl.
- No account, no backend, no build step, no tracking script.
- History and presets are stored in `localStorage` on the visitor's own device.
- MIT licensed; the repository is public; the test suite runs in the browser.
- Inputs up to 10 MiB.
- 7 formats (JSON, YAML, TOML, CSV, TSV, XML, HTML tables), 49 pairs.
- Hashes: SHA-256, SHA-384, SHA-512, SHA-1, MD5.
- cURL translates to fetch, axios and Python requests.

**Do not say:**

- That it works offline or is a PWA — the offline feature flag is off.
- That JWT signatures are verified. They are **not**, and the site says so.
- Any user, download or star count. There are none yet, and inventing one is
  the fastest way to lose the room.
- That it is "the fastest" or "the best" anything — unmeasured and unnecessary.
- Anything about a paid tier, an API or a roadmap that does not exist.

**Useful and honest to admit:** that plenty of these tools already exist, that
CSV detection is a heuristic that is sometimes wrong, and that the reason to
use this one is verifiability rather than novelty. Saying so earns more trust
than any claim about being better.
